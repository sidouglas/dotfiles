**Platform-specific selection context (TST-03 / GEN-01):**
Add a nested context inside `"when specification is social"`:
```ruby
context "when rule has platform-specific selection (only tweet)" do
  let(:scheduled_report_specification) do
    create(
      :scheduled_report_specification,
      :user => user,
      :sections => [
        create(
          :scheduled_report_specification_section,
          :rules => [
            create(
              :scheduled_report_specification_rule,
              :stream => social_stream,
              :social_content => [:tweet]
            )
          ]
        )
      ],
      :media_order => ["tweet"],
      :group_by_media => true,
      :product_type => "social"
    )
  end

  it "only includes tweet content", :indexed_content do
    grouped_mentions = subject
    items = grouped_mentions[0]["items"]
    expect(items.size).to eq(1)
    expect(items[0][:type]).to eq "tweet"
  end
end
```
This overrides only the `scheduled_report_specification` let — the existing `tweet` and `facebook_post` fixtures remain indexed. The assertion proves that `facebook_post` (which IS indexed) is excluded because the rule only selects `[:tweet]`.

Note: The existing context's `enable_features` call already enables `:social_mentions`, `:has_social_platform`, `:view_tweet`, `:view_facebook_post`. For the tweet-only test, this is fine -- the feature flags permit both but the rule's `enabled_media_types` only returns `[:tweet]` because only that bit is set.
